## 1. Claude-Code-Game-Studios
- Що це: шаблон репо для Claude Code: 49 агентів (директори, лиди відділів, спеціалісти), 75 скілів, 18 bash-hooks, 14 path-scoped rules, genres/engines docs.
- Рушії: web (default; three.js/Phaser/PixiJS), Godot 4, Unity, UE5. Тобто three.js/TypeScript підтримується прямо.
- Що ставить: використовується як шаблон (clone у проєкт). Не MCP-сервер. Але приносить `.claude/settings.json` з 15 hooks (SessionStart, PreToolUse на Bash/Write/Edit/Read, PostToolUse, Stop, SubagentStart/Stop), statusLine-скрипт, allow/deny permissions.
- Мережа: прочитаний `update-check.sh` робить GET на api.github.com (releases/latest) через curl, кеш у ~/.cache, вимикається `updates.check: false` або CI. Телеметрії нема. Решту 17 hooks не читано (тільки settings.json) - перед запуском їх треба переглянути.
- Конфлікти з нашими правилами:
  - Власний `CLAUDE.md` у корені перезапише/зіткнеться з нашим; hooks на Read/Write додають латентність і можуть конфліктити з правилом "graphify спершу".
  - Hooks на SubagentStart/Stop + 49 агентів суперечать "одна задача за раз" і економії токенів (багато делегування, багато контексту).
  - Дозволяє частину `.claude/scripts/*.sh` без підтвердження; settings.json project-level, не user, але заміщає наші project-налаштування, якщо вже є.
- Реально корисне для соло-розробника: skills з game design (GDD), QA/playtest-чеклісти, code review, release/sprint, ADR. Агентний "корпоративний" шар (директори, producer) - зайвий.
- Рекомендація: НЕ клонувати як шаблон. Окремо прочитати 5-10 потрібних SKILL.md і перенести їх вручну в `.claude/skills/` (за потреби), без hooks, settings.json, CLAUDE.md, statusline. Ризик supply-chain низький (MIT, текст/bash), але bash-hooks виконуються автоматично, тому лише після ручного ревью.

## 2. UnrealClaude
- Плагін UE 5.7: панель чату + MCP-сервер (20+ інструментів: актори, Blueprint, матеріали) на localhost:3000.
- Запускає `claude` CLI з `--skip-permissions` і дозволеними Bash/Write; автентифікації на порту 3000 не описано. Збірка з сирців (RunUAT BuildPlugin), `npm install` у mcp-bridge (npm supply-chain). Автор сам пише, що Blueprint-редагуванню не можна повністю довіряти.
- Потрібно: UE 5.7, Win/Linux/macOS Apple Silicon.
- Для Ashfall корисність нульова, поки ми на three.js. Якщо колись UE - тільки в ізольованому проєкті.

## 3. godot-mcp
- MCP-сервер (npx @coding-solo/godot-mcp): запуск редактора/проєкту, сцени, вузли, debug output; частину операцій виконує через GDScript.
- 6.7k зірок, MIT; `npx` без піна версії (ризик supply-chain), Godot потрібен локально.
- Ashfall не на Godot. Пропустити.

## 4. ACE-Step 1.5
- Локальна генерація музики (ACE Studio + StepFun). Код MIT. Ліцензія ваг на сторінці НЕ вказана (дивитись Hugging Face model card); явних умов комерційного використання виходів на сторінці немає - до релізу з'ясувати. Дисклеймер просить розкривати участь AI.
- Мак: Apple Silicon підтримується (MPS + MLX скрипти), Python 3.11-3.12, `uv sync`, `uv run acestep` (Gradio :7860) або `acestep-api` (:8001). Вага моделей завантажується з HF. 2B turbo ≈ ≤6 GB VRAM; XL ≥12 GB з offload. На Mac швидкість буде значно нижча за заявлену (A100 <2 с) - не перевірено.
- Тривалість 10 с - 10 хв; є stems-розділення, repaint, multi-track ("Lego"). Це придатне для генерації окремих шарів/луп, але адаптивні шари (синхронні за темпом/тональністю) треба збирати вручну; спеціальної функції loop нема. Якість "між Suno v4.5 і v5" - твердження авторів, незалежно не перевірено.
- Ставити: у ізольований каталог/venv, не в репо гри. Ризик: pickle/ваги з HF (завантажувати з офіційного репо), порти тільки на localhost.
- Вердикт: дешевий експеримент для темних ambient-шарів (1 вечір). Для гри це "корисно", не "критично".

## 5. Audio2Face-3D
- Хаб NVIDIA: SDK (C++/Python, MIT), training framework (Apache), плагіни Maya/UE (MIT), NIM (докер, окрема ліцензія), моделі onnx-trt (NVIDIA Open Model license), Audio2Emotion (лише з A2F), датасет - тільки evaluation.
- Вихід: blendshape-ваги / деформації / joints. ARKit-іменування на сторінці не згадано - треба перевіряти. Вимоги до GPU/CUDA не вказані; формат onnx-trt означає NVIDIA GPU + TensorRT. На Mac (наша машина) практично не запуститься; потрібна NVIDIA-машина або хмара/NIM.
- Веб/three.js: прямого шляху нема. Реалістично: офлайн-бейк (аудіо -> криві blendshape -> JSON/glTF morph-target animation) для заздалегідь записаних реплік. Рантайм-lip-sync у браузері не потрібен.
- Наша проблема "обличчя без виразу": A2F цього не вирішує - у MPFB2-голови нема достатньо face-блендшейпів/рига, а AI-обличчя з Higgsfield статичні. Спершу потрібен facial rig (ARKit 52 або FACS-морфи). Для lip-sync у вебі простіші альтернативи: viseme-driven морфи за аудіо (напр. Rhubarb Lip Sync, Oculus-visemes) - ці альтернативи я не перевіряв у цій сесії.
- Вердикт: пропустити зараз; повернутись, якщо з'явиться озвучка і ARKit-риг.

## (a) Чи варто мігрувати Ashfall на Unreal?
Рекомендація: ні.

Вартість:
- Переписування: `packages/engine` (TS-симуляція), `apps/web` (React+three.js UI/рендер), Go-сервер - усе під C++/Blueprint + інший мережевий шар. Для соло-розробника це місяці без нового геймплею.
- Веб: HTML5-експорт UE видалено ще в UE5; браузерний запуск = Pixel Streaming (GPU-сервер на кожного гравця, дорого, латентність) або завантажуваний білд. Це ламає поточну модель Vercel+Railway і "відкрий посилання - грай".
- Мультиплеєр: наш Go-сервер + детермінована TS-sim замінюється на UE replication/dedicated server; окрема інфраструктура.
- Персонажі: MetaHuman дає найкращий face-риг, але ліцензію (EULA) щодо використання поза UE і особливо щодо дорослого/оголеного контенту треба читати первинно - я це в сесії не перевіряв. Для nude-налаштування це може бути блокером (і політики сторів теж).
- Команда: UE-пайплайн розрахований на команду з 3D/анімації/C++; соло з Claude Code краще працює у TS, де AI-агенти сильні і ітерація миттєва.

Вигоди: Nanite/Lumen, MetaHuman, Control Rig, готові анімаційні інструменти, UnrealClaude. Але це вирішує візуальну проблему тіл/облич, яку можна вирішити точково (референс, facial rig, ретаргет), без зміни рушія.

Альтернатива: лишитись на three.js; для облич - ARKit-морфи на голові (Blender, експорт glTF); якщо дуже потрібен MetaHuman - використовувати його лише як генератор ассетів у окремому UE-проєкті й експортувати (за умови, що ліцензія дозволяє).

## (b) Що брати і в якому порядку
1. Нічого глобально не встановлювати. Спершу (0 ризику): вручну переглянути в репо CCGS 5-10 скілів (GDD, QA/playtest, code review, release checklist) і скопіювати потрібні тексти в `.claude/skills/` проєкту; hooks/settings.json/CLAUDE.md не переносити.
2. ACE-Step 1.5 (опційно, пізніше): окрема тека поза репо, `git clone` + `uv sync` + `uv run acestep`; перед комерційним використанням прочитати ліцензію ваг на Hugging Face. Ризики: розмір моделей, повільно на Mac.
3. Audio2Face-3D: відкласти до готового ARKit-рига і озвучки.
4. UnrealClaude, godot-mcp: не брати.

Головне: проблеми Ashfall (тіла, обличчя) - це проблема референсу/рига, а не рушія; міграція її не вирішує і знищує веб-модель дистрибуції.
